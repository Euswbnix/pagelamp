# PageLamp v0.3 给 owner 的简报（2026-09-27，2026-09-28 更新）

详细版本见 `v0.3-plan.md`（计划，第 3 版）、`v0.3-model-access.md`（设计，第 3 版）和 `v0.3-course-calendar.md`（课程日历与往期课程，9-28 新增）。本简报已经吸收了 9-27 和 9-28 的评审意见。9-28 新增的内容见最后一节。

## v0.3 做什么

- **PageLamp 自己调用模型**，生成四样东西：
  - 按天排的学习计划：模型只看课程结构，日期由确定性的排程器排；
  - 每周内容讲解：会发送课件正文，每一段都带出处；
  - 每周进度提醒：不需要模型；
  - 课程日历（9-28 新增）：读 syllabus 和 schedule（会发送这部分正文），和教授资料一起算出每门课进行到哪，见最后一节。
- **接入方式，按优先级：**
  1. 用 ChatGPT 订阅：PageLamp 按需下载 OpenAI 官方、未修改的 Codex，由 Codex 自己完成登录。
  2. 用 Claude 订阅：调用学生自己装的 Claude Code。**等 Anthropic 书面确认后才开放。**
  3. 学生自己的 API key（进阶选项）。
  4. 本机模型（Ollama / LM Studio）。
  5. v0.1 的反向 MCP 路径继续保留，零配置可用。
- **不变的原则：**
  - 不代理或转售额度，不碰订阅 token；
  - 拒绝 Coding Plan 类 key；
  - 每次调用模型前都要过课程 AI 政策这一关；
  - 不做作业，也不抓取作业要求。
- **v0.3 一开始先做：** Tauri 自动更新、PDF 解析子进程（extraction worker）、课程周数修复。签名已经在 v0.1.0 完成（macOS 和 Windows 都已签名）。

## 主要风险

- **Apple / Azure 审核拖期**：已解除，v0.1.0 已签名发布。
- **UofT 的学生指引**："未经老师许可，避免上传或分享老师的内容（包括讲义）"。按你的决定默认照常发送、只做提醒，这条风险由学生自己判断；学生标"不允许"的课绝不发给云端（见下面的 D37）。
- **OpenAI 可能回复"请用 API key"**：那 ChatGPT 订阅模式就撤掉，改为引导学生用 API key、本机模型或 MCP。
- **学生的钱**：
  - Codex 超出套餐后可能扣 ChatGPT credits，对策是披露、每周运行次数上限、显示每次的 token 数；
  - API key 费用超支，对策是保守的预估，点 Generate 前先显示"≈ $x"。
- **更新出错会困住用户**：alpha.1 发布前先在测试通道完整跑一遍更新；准备"坏版本"处置手册；每次数据库迁移前自动备份。
- **只有一条后端开发线**：M1 最紧。砍功能的顺序已经定好，但政策闸门测试和签名/更新永远不砍。课程日历由另外的 backend-2、frontend-2 并行开发，不占这条线（D41 只决定它们是否用独立的 worktree）。
- **固定版本的 Codex 可能突然失效**：OpenAI 换了账号的默认模型后，旧版 Codex 会报 "requires a newer version of Codex"（9-28 实测）。对策：每次运行都明确指定模型，出错时提示"PageLamp 需要更新 Codex"或"请更新 PageLamp"，并按时和出错时更新固定版本。

## 课程日历与往期课程（2026-09-28 新增）

详细设计见 `v0.3-course-calendar.md`。

### 你报告的问题

- **"第 22 周"**：你 Fall 2026 的几门课都显示"第 22 周 · 中等置信度"。
  - Canvas 给 UofT "Fall 2026" 的学期是 2026-05-04 到 2027-01-31。这是选课窗口，不是上课时间。
  - v0.1 从 5 月 4 日起每 7 天数一周，9 月 28 日正好是第 22 周；只有超过 30 周才会被当成异常。
  - v0.1 的"日期不对？"表单也预填了这个窗口。
- **往期课程一直在**：2024 夏、2025 冬、2025 秋的几门课还在同步。
  - 教授没有结课，Canvas 仍把它们列为"进行中"。
  - v0.1 只能隐藏，下载的文件还留在电脑上。
- v0.1.0 的发布说明已经把这两条列为已知问题，并承诺在 v0.3 修好。

### v0.3 的做法

- **alpha.1（10-18），不用 AI 先修好周数：**
  - 识别"选课窗口"式的学期，不再拿它数周；
  - 改用课程自己的日期、UofT 场次码（只作日期范围），以及教授资料里的 "Week N" 和发布时间，推出第 1 周；
  - 显示"上课 / 休息周 / 考试 / 已结束"；
  - 已结束的课自动收进 "Past"，不再进入每周摘要、学习计划和 AI 应用的每周提示；它们的截止日期照常提醒；
  - v0.1 表单里原样预填、你没有改过的日期会被自动清掉，不会出现"考试期显示第 15 周"。
- **alpha.2（11-08），删除：**
  - 单门或批量删除，课程马上从所有列表和 AI 应用里消失，同步不会再把它带回来；
  - 7 天内一键撤销；7 天后清除本地数据，下载的文件移进废纸篓；
  - 你自己文件夹里的文件永远不动；
  - 另有可以填 reading week 和考试期的"课程日期"表单。
- **alpha.3（11-22），AI 读 syllabus 和 schedule（这项不会被砍；如果发布前的检查没全部通过，先只给团队用，最晚 beta.1 对所有人开放）：**
  - AI 只负责"抄"：每个日期都必须引用资料里真实存在的原文，并且能从这段原文里读出来；年份和周数由程序计算；
  - 和教授资料的周号交叉核对，不一致会提示；
  - 结果是提议，你点一下才生效；接受以后仍然标明是哪个 AI 读出来的；
  - 同一版本还有不用模型的"大纲扫描"，没配模型的同学也能用；
  - 大纲 PDF 还没下载时，提供"一键下载（会在 Canvas 里记为查看）"，不会自动下载。
- **beta.1（12-06）：**
  - 你自己的 AI 应用可以经 MCP 提议日历（可削减）；
  - 计划、讲解、提醒改用新的周数和课程状态。

### 不变的规则

- 模型只在你发起时运行（唯一的例外是你可选开启的周一 weekly note，D27）；
- 标了"禁止使用 AI"或关掉 AI 访问的课，AI 不读正文，但本地的日期扫描照常；
- 发给云端之前，照你 9-25 的决定只提醒、不阻拦（D37 方案 2）；只有答"不允许"的课绝不发给云端。
