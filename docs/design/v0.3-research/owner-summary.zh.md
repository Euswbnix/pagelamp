# PageLamp v0.3 给 owner 的简报（2026-09-27）

详细版本见 `v0.3-plan.md`（计划，第 2 版）和 `v0.3-model-access.md`（设计，第 3 版）。本简报已经吸收了 9-27 的评审意见。

## v0.3 做什么

- **PageLamp 自己调用模型**，生成三样东西：
  - 按天排的学习计划：模型只看课程结构，日期由确定性的排程器排；
  - 每周内容讲解：唯一会发送课件正文的功能，每一段都带出处；
  - 每周进度提醒：不需要模型。
- **接入方式，按优先级：**
  1. 用 ChatGPT 订阅：PageLamp 按需下载 OpenAI 官方、未修改的 Codex，由 Codex 自己完成登录。
  2. 用 Claude 订阅：调用学生自己装的 Claude Code。**等 Anthropic 书面确认后才开放。**
  3. 学生自己的 API key（进阶选项）。
  4. 本机模型（Ollama / LM Studio）。
  5. v0.1 的反向 MCP 路径继续保留，零配置可用。
- **不变的原则：**
  - 不代理或转售额度，不碰订阅 token；
  - 拒绝 Coding Plan 类 key；
  - 每次调用模型前都要过课程 AI 政策这一关；
  - 不做作业，也不抓取作业要求。
- **v0.3 一开始先做：** 签名发布、Tauri 自动更新、PDF 解析子进程（extraction worker）。

## 主要风险

- **Apple / Azure 审核拖期**：会推迟 alpha.1。备选有 SignPath，以及决策 D38。
- **UofT 的学生指引**："未经老师许可，避免上传或分享老师的内容（包括讲义）"。按你的决定默认照常发送、只做提醒，这条风险由学生自己判断；学生标"不允许"的课绝不发给云端（见下面决策 3）。
- **OpenAI 可能回复"请用 API key"**：那 ChatGPT 订阅模式就撤掉，改为引导学生用 API key、本机模型或 MCP。
- **学生的钱**：
  - Codex 超出套餐后可能扣 ChatGPT credits，对策是披露、每周运行次数上限、显示每次的 token 数；
  - API key 费用超支，对策是保守的预估，点 Generate 前先显示"≈ $x"。
- **更新出错会困住用户**：alpha.1 发布前先在测试通道完整跑一遍更新；准备"坏版本"处置手册；每次数据库迁移前自动备份。
- **只有一条后端开发线**：M1 最紧。砍功能的顺序已经定好，但政策闸门测试和签名/更新永远不砍。

## 需要你拍板的决策（附建议）

1. **D36 v0.1.0 怎么发**：你已决定不做多日的同学试用，自己测完就发。建议按**正常版本**发布（第一个公开版本，给 GitHub 和 UTM MCS 群），README 加一句"0.1 不会自动更新"。自动更新的正式通道从 v0.3.0 才开始，所以 0.1.0 先占着"最新版本"不影响任何东西。（10-04）
2. **D38 Windows 签名都没办下来时，beta.1 能不能不签名发 Windows 版**：建议可以，但只给受邀学生，并附 SmartScreen 说明；v0.3.0 正式版在 Windows 上绝不无签名。（10-04）
3. **D37 课件能不能发给云端模型**：每门课可以选答一句"这门课的课件能分享给 AI 服务吗？"。建议照你 9-25 的决定用 **方案 2**：没回答或"不确定"也照常发送，只在这门课第一次生成讲解时给一次不拦截的提醒，并在结果上注明课件发给了哪个服务；只有学生选"不允许"才绝不发给云端（改用本机模型或只用课程结构）。方案 1 是评审建议的严格版：答"可以"才发送，完全照 UofT 的学生指引，代价是每门课第一次都要先回答。两种方案下"不允许"都在底层强制执行，反向 MCP 不变。（11-15）
4. **D39 / D35 beta.1 和正式版的时间**：建议 beta.1 定在 12-06（考试前），AI 周记放到 beta.2（12-23）；正式版 01-08，顺延规则见上。（10-18）
5. **D40 Intel Mac**：你的 Mac 测不了 Intel 版。建议接受这个风险，在 CI 的 `macos-15-intel` 机器上跑一个启动冒烟测试（GitHub 提供到 2027 年 8 月）。（10-18）
6. **D2 更新检查默认开启**：建议开启，但安装前一律先问；从 0.1 升级上来的用户，在第一次自动检查之前先看一次"新功能"说明。（10-04）
