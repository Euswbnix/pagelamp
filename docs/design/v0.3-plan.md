**M0.5 Extraction worker (backend, leader for Swift)**
- **Process:** the hidden `pagelamp extract-worker --protocol 1`, one process per file, JSON over
  stdin/stdout. The environment is cleared, so no `PAGELAMP_SECRET_*` reaches it. On Windows it is
  spawned with `CREATE_NO_WINDOW`, so the GUI app doesn't flash a console.
- **Limits:**
  - a counting global allocator: the only memory cap that works on macOS, where the rlimits
    don't [18];
  - Unix: `RLIMIT_CPU`, `RLIMIT_CORE=0`, `RLIMIT_FSIZE=0`; Linux also gets `RLIMIT_AS`;
  - Windows: a Job Object (memory, CPU time, kill-on-close, no crash dialog) [19];
  - the parent sets a wall-clock timeout (120 s) and polls the child's footprint on macOS.
- **Failure classes** go into the new `materials.text_error_kind` (schema v3): `timed_out`,
  `cpu_limit`, `memory_limit`, `crashed`, `bad_output`, `spawn_failed`, `protocol_mismatch`.
- **No retry loops.** Today `is_indexed` skips only `TextStatus::Ok`, so a file that timed out
  would be re-extracted on every sync. v3 skips a file while its (`content_hash`, worker protocol,
  app version) match a stored hard failure.
- **Fallback rule.** `spawn_failed` or `protocol_mismatch` usually means antivirus or Smart App
  Control blocked the worker, which is exactly when in-process parsing is riskiest.
  - Fall back in-process only for **small non-PDF** files (proposed ≤ 5 MB, text/HTML/Office).
  - Everything else is marked and retried on the next sync.
  - Either way a `SyncEvent::Warning` is sent and `doctor` gets a check.
- **Spawn cost.** Measure the per-file spawn cost on Windows CI, and set a budget from the result
  (proposed: median ≤ 150 ms **[estimate]**).
- **Facade:** `App::set_extract_worker(Option<PathBuf>)`. Each surface passes its path:
  - desktop: `backend::pagelamp_binary()`;
  - CLI: `current_exe()`;
  - Swift: `Bundle.main.url(forAuxiliaryExecutable:)`.
- **Diagnostics:** `diagnostic_report` counts unreadable files by class.

    **[verify at implementation]**.

## 6. Risks and mitigations

| Risk | Likelihood / impact | Mitigation |
|---|---|---|
| Apple enrolment or Azure validation delays | resolved 2026-09-28 (v0.1.0 shipped signed on macOS and Windows) | kept for reference: A1/A2 done; SignPath fallback (A3) only if Azure breaks; D38 |
| The rehearsal can't reach the secrets (environment rule vs `GITHUB_REF`) | resolved 2026-09-28 (the owner set the `main` and `v*` rules) | `release` allows `v*` tags and `main` [20]; re-runs dispatched with the tag as ref |
| Signing secrets read by a compromised dependency during the build | low / severe | compile step without secrets, bundle step with them; step-scoped env; `--locked`; `cargo deny` advisories; SHA-pinned actions [12] |
| Updater key lost or leaked | low / severe (no updates, or malware to every install) | password manager + offline copy (A4); secrets only in the `release` environment with reviewer; immutable releases [10] |
| A broken updater or migration strands installs | low–medium / severe | the update loop tested on a test channel before alpha.1; "bad release" runbook; pre-migration backups; updater errors in the log and report |
| Betas never see the final release (numeric bundle version) | certain without the fix / high | custom comparator + a test (M0.4) |
