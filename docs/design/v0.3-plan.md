### 1.3 Working rules that apply to every milestone

- ARCHITECTURE §2 ownership, §8 DoD and the git workflow are unchanged: pathspec commits, push at
  ≥5 local commits, no Claude trailers.
- Contract changes (§3–§5) go through the leader. Each milestone below lists them.

  reminder catch-up, startup tasks, the per-course policy questions and the disclosure facts. The

**M0.4 Updater (frontend, leader for the manifest)**
- **Plugin setup:**
  - `tauri-plugin-updater` from Rust only; the webview gets no `updater:*` permission;
  - `createUpdaterArtifacts: true`;
  - the pubkey is in `tauri.conf.json` [1].
- **Version comparison fix.** `tauri.conf.json` keeps the numeric version because MSI rejects
  pre-release versions, so the updater would compare betas as equal to the final release. Fix:
  a custom comparator against `CARGO_PKG_VERSION` [13].
- **Windows:** NSIS only (per user); drop MSI (D4).
- **NSIS pre-install hook** that renames a running `pagelamp.exe` aside. The NSIS template only
  checks the main exe [15], and Claude Desktop keeps the sidecar locked.
- **deb/rpm:** "update available" plus a download link. The manifest publishes no generic
  `linux-x86_64` key, which would make the updater `dpkg -i` an AppImage [13].
- **Our own manifest.** A leader script, `.github/scripts/updater-manifest.mjs`, writes plain
  `releases/download/<tag>/` URLs.
  - It doesn't use tauri-action v1's API asset URLs, because unauthenticated API use is limited to
    60 requests per hour per IP, and a campus NAT could hit that [16][17]. Whether asset downloads
    count is **[unverified]**.
  - It fails if any platform is missing.
- **Channels:** stable reads Pages `updates/stable.json`, then `releases/latest/download/latest.json`;
  beta reads Pages `updates/beta.json`. `channels.yml` moves them when a release is published.
- **Test channel.** Before alpha.1 is published, the update loop is tested end to end. Two
  rehearsal builds, N and N+1, are made with a `rehearsal` config overlay that points the updater at
  Pages `updates/test.json`; release builds can't be pointed elsewhere. N+1's artifacts are hosted
  under `updates/test/` for the test and deleted afterwards.
- **Settings → Updates:**
  - channel, automatic check (D2), Check now;
  - Install and restart, which warns on Windows that PageLamp will close. It is **disabled while
    `activity()` shows a sync, a generation or a Codex install**, with an offer to cancel them.
    On Windows the app "is automatically exited when the install step is executed" [1], so the
    `on_before_exit` hook also waits (bounded) for cancellation;
  - a post-update banner: "quit and reopen your AI app".
- **Upgraders** from 0.1 see a one-time "What's new" sheet (design §7) before the first automatic
  check, because they never saw the onboarding disclosure of the update check.
- **Errors:** updater errors go to the PageLamp log, and `diagnostic_report` gains the last
  update-check result (counts and codes only).

**M0.5 Extraction worker (backend, leader for Swift)**
- **Process:** the hidden `pagelamp extract-worker --protocol 1`, one process per file, JSON over
  stdin/stdout. The environment is cleared, so no `PAGELAMP_SECRET_*` reaches it. On Windows it is
  spawned with `CREATE_NO_WINDOW`, so the GUI app doesn't flash a console.
- **Limits:**
  - a counting global allocator: the only memory cap that works on macOS, where the rlimits
    don't [18];
  - Unix: `RLIMIT_CPU`, `RLIMIT_CORE=0`, `RLIMIT_FSIZE=0`; Linux also gets `RLIMIT_AS`;
  - Windows: a Job Object (memory, CPU time, kill-on-close, no crash dialog) [19];
  - the parent sets a wall-clock timeout (120 s) and polls the child's footprint on macOS.
- **Failure classes** go into the new `materials.text_error_kind` (schema v3): `timed_out`,
  `cpu_limit`, `memory_limit`, `crashed`, `bad_output`, `spawn_failed`, `protocol_mismatch`.
- **No retry loops.** Today `is_indexed` skips only `TextStatus::Ok`, so a file that timed out
  would be re-extracted on every sync. v3 skips a file while its (`content_hash`, worker protocol,
  app version) match a stored hard failure.
- **Fallback rule.** `spawn_failed` or `protocol_mismatch` usually means antivirus or Smart App
  Control blocked the worker, which is exactly when in-process parsing is riskiest.
  - Fall back in-process only for **small non-PDF** files (proposed ≤ 5 MB, text/HTML/Office).
  - Everything else is marked and retried on the next sync.
  - Either way a `SyncEvent::Warning` is sent and `doctor` gets a check.
- **Spawn cost.** Measure the per-file spawn cost on Windows CI, and set a budget from the result
  (proposed: median ≤ 150 ms **[estimate]**).
- **Facade:** `App::set_extract_worker(Option<PathBuf>)`. Each surface passes its path:
  - desktop: `backend::pagelamp_binary()`;
  - CLI: `current_exe()`;
  - Swift: `Bundle.main.url(forAuxiliaryExecutable:)`.
- **Diagnostics:** `diagnostic_report` counts unreadable files by class.

**M0.6 Pipeline hygiene (leader)**
- **The `release` environment** holds every secret, with the owner as required reviewer [11].
  - Its deployment rules allow **tags `v*` and the protected branch `main`**. GitHub matches the
    rule "against the `GITHUB_REF` of the workflow run" [20], and the rehearsal workflow runs from a
    branch, so a tags-only rule would never give it the secrets.
  - Manual re-runs of `release.yml` must be dispatched **with the tag as the ref**
    (`--ref v0.3.0-alpha.1`), not from a branch.
- **Secrets are scoped to the step that needs them**, never to the job, because build scripts,
  proc-macros and "dependency lifecycle hooks" in the same job can read job-level environment
  variables (OpenAI's CI guidance, design [2]).
  - Compile first without secrets: `pnpm tauri build --no-bundle -- --locked`, which runs every
    dependency's build scripts and proc-macros.
  - Then run `pnpm tauri bundle` in a separate step that holds the Apple, notary and updater
    secrets. Tauri's CLI has both commands [28].
  - The bundler requires `TAURI_SIGNING_PRIVATE_KEY` when the pubkey and updater artifacts are
    configured [28], so the updater key goes in that bundle step.
  - Whether tauri-action can drive the two steps, or the workflow calls the CLI directly, is
    **[verify at implementation]**.
- **Supply chain:**
  - `--locked` on every cargo build;
  - `cargo deny check advisories licenses` in `release.yml`;
  - all actions pinned to full SHAs (the tj-actions compromise [12]).
- **Toolchain:**
  - bump `rust-version` to **1.90** (the root `Cargo.toml`);
  - pin Tauri to 2.x for v0.3, so `tauri` 3.0.0-alpha.3 (Rust 1.95) is never picked [21];
  - then add `tauri-plugin-updater` ≥ 2.13.
- **Workflows:**
  - `release-rehearsal.yml` (manual, from `main`) builds signed artifacts without a release;
  - `ci.yml` builds the desktop app on Windows;
  - a `release-config` job checks: pubkey present, no MSI, no entitlements, manifest-script tests,
    no job-level secrets in any workflow.

**"Bad release" runbook (M0.7)**
1. Revert `updates/stable.json` / `beta.json` on Pages to the previous release. This stops further
   spread; it can't roll anyone back.
2. Ship N+1 from a **new tag**. Immutable releases forbid fixing assets in place [10].
3. For a broken migration: each migration leaves `pagelamp.db.v<N>.bak` (design §5.4). The runbook
   says how to restore it with the older build.
4. Look at updater errors in the local log and `diagnostic_report`.

- Windows signing waits on A2/A3.

2. **Update loop tested before alpha.1 is published:** rehearsal build N updates to N+1 over the

3. **Owner test A11 on a Mac**, all of these:
   - browser-download install in a fresh user account opens without Privacy & Security;

   - upgrading from the 0.1 build: note any keychain prompt.
4. **Worker:**
   - `apps/pagelamp-cli/tests/extract_worker.rs` classifies synthetic bombs (built with `lopdf`)

## 6. Risks and mitigations

| Risk | Likelihood / impact | Mitigation |
|---|---|---|
| Apple enrolment or Azure validation delays | medium / blocks signing | start now (A1/A2); SignPath fallback (A3, after the first public release); D38; M1 work continues on `main` |
| The rehearsal can't reach the secrets (environment rule vs `GITHUB_REF`) | certain with a tags-only rule / blocks M0 DoD | `release` allows `v*` tags and protected `main` [20]; re-runs dispatched with the tag as ref |
| Signing secrets read by a compromised dependency during the build | low / severe | compile step without secrets, bundle step with them; step-scoped env; `--locked`; `cargo deny` advisories; SHA-pinned actions [12] |
| Updater key lost or leaked | low / severe (no updates, or malware to every install) | password manager + offline copy (A4); secrets only in the `release` environment with reviewer; immutable releases [10] |
| A broken updater or migration strands installs | low–medium / severe | the update loop tested on a test channel before alpha.1; "bad release" runbook; pre-migration backups; updater errors in the log and report |
| Betas never see the final release (numeric bundle version) | certain without the fix / high | custom comparator + a test (M0.4) |
| Windows sidecar locked by the AI app during an update | likely / install failure | NSIS rename hook; "quit your AI app" text; tested in A11 |
