# v0.3 design — embedded model access ("full" StudentOS)

Status: **draft for later** (leader, 2026-09-25). Not in scope for v0.1. Based on two research
rounds with adversarial fact-checks (sources in the session research archive); every vendor fact
below must be re-verified at implementation time — this space changes monthly.

## 1. Goal

StudentOS itself generates study plans, weekly explanations and catch-up summaries (and later a
read-only coding tutor), instead of relying only on the student's AI app over MCP. The local MCP
server from v0.1 stays as the zero-configuration path for every student.

## 2. Access modes, in order of how many target students they serve

Most target students have a ChatGPT or Claude **subscription**, few have API keys.

| Mode | How | Status / caveats |
|---|---|---|
| 0. Reverse MCP (v0.1) | Student's Claude Desktop / ChatGPT desktop (Work/Codex mode) / Claude Code / Codex reads StudentOS over local MCP | Documented and allowed. No proactive generation (no MCP sampling: deprecated in spec 2026-07-28, unsupported by Claude). |
| A. ChatGPT subscription | Bundle the **unmodified official Codex** binary; Codex runs its own "Sign in with ChatGPT"; StudentOS drives `codex exec --json --output-schema` (Stable) — `app-server` only if needed (Experimental, "not supported for production workloads"). Tools off (`features.shell_tool=false`, web search disabled, `--ignore-user-config`, `--ephemeral`). | OpenAI docs invite embedding the Codex harness and say Codex may be used for non-coding knowledge work. Programmatic use is documented for Plus and above + Edu; **Free/Go via CLI is undocumented — test first.** Codex for Students credits (US/Canada) are usable here. Never touch the tokens; never run it for other people. |
| B. Claude subscription | Student's own **unmodified Claude Code** (`claude -p`, `--system-prompt`, `--output-format json`), logged in by Claude Code itself | Anthropic's legal page permits products to run the unmodified binary with the end user's own subscription, but other clauses ("route … against subscription limits", "use an API key when building for others") make it a **gray area → get written confirmation from Anthropic first**; developer must accept Commercial Terms. Paid plans only (Free has no Claude Code). Risk: `--bare` becoming the `-p` default (it does not read OAuth). |
| C. BYOK API key | StudentOS's own Rust `llm` layer (§3) | Fully under our control; the only mode that can enforce tutor behaviour end-to-end. |
| D. Local model | Ollama / LM Studio via the same layer | Materials never leave the device; quality limited on laptops — use for summaries, not deep explanations. |

Rejected: Claude Agent SDK with claude.ai login (prohibited without approval); asking students to
paste `claude setup-token` / subscription tokens (prohibited); re-implementing Codex OAuth against
`chatgpt.com/backend-api` (undocumented); reverse-engineered web APIs / cookie scraping (ToS
violation); any relay/proxy server of ours.

## 3. BYOK provider layer (`crates/studentos-llm`)

Decision: **write a thin in-house layer**; do not hand "any model" to a third-party library.
- Wire drivers: **OpenAI Responses**, **OpenAI-compatible Chat Completions** (dialect layer for
  everyone else), **Anthropic Messages** (native — Anthropic's OpenAI-compat endpoint is "for
  testing" and silently drops `response_format`, `strict`, PDFs, caching, thinking). Optional:
  Ollama native, Gemini native (Gemini starts on its OpenAI-compatible endpoint).
- Responses cannot be skipped: newest OpenAI models restrict tool calling on Chat Completions and
  file inputs / reasoning continuation are Responses-only.
- reqwest + SSE + `serde_json::Value` pass-through: the IR must round-trip **opaque reasoning
  state** verbatim (OpenAI encrypted reasoning items, Anthropic thinking signatures, Gemini
  thoughtSignature, DeepSeek/Kimi `reasoning_content`, OpenRouter `reasoning_details`) —
  dropping it causes 400s in tool loops.
- **Data-driven provider profiles** (base_url, region, wire, auth header, quirk flags, capability
  flags) + model catalog from models.dev (MIT) with our own overlay, **verified at runtime** by a
  "test connection" probe (tool calling, json_schema, thinking toggle). Quirk vocabulary: borrow
  pi-ai's `OpenAICompletionsCompat` flags.
- Keys only in the OS keychain; no Node/Python sidecar (LiteLLM had a PyPI supply-chain
  compromise in 2026-03; new-api is AGPL). `rust-genai` (MIT/Apache) = reference / plan B behind
  our trait, pinned.
- Settings page: explicit platform picker (key prefixes can't identify vendors — many use `sk-`),
  prefilled editable base URL/region, key → keychain, fetched model list, test connection, and a
  per-provider data-policy line (training / retention / data location) for Canvas §2E disclosure.

Provider presets for our audience (students outside mainland China):
- Tier 1: OpenAI, Anthropic, Google Gemini, OpenRouter (one key → many models), Ollama/LM Studio,
  generic OpenAI-compatible.
- Tier 2 (advanced, **international endpoints only**): DeepSeek, Alibaba Model Studio (intl),
  Moonshot (api.moonshot.ai), Z.ai, MiniMax (minimax.io), BytePlus ModelArk.
- Not presets: Volcengine Ark (its terms license use in mainland China only), Baidu Qianfan.
- **Refuse "Coding Plan / Token Plan" keys** (Ark/BytePlus/Alibaba/Z.ai/Qianfan coding endpoints):
  their terms forbid use outside coding tools / as an app backend. Detect by base URL.

## 4. Feature design (model-agnostic by construction)

- **Per-feature model routing** (plan / weekly explanation / follow-up / summary / tutor), each
  gated by required capabilities; cheap model for summaries.
- **Explicit thinking policy per feature** — most current models think by default (cost + latency);
  turn it off/low for summaries.
- **Structured output in three tiers**: native strict json_schema → json_object → prompt-only;
  always a lowest-common-denominator schema + local JSON-Schema validation + repair/retry.
- **Study-plan dates come from a deterministic scheduler**; the model only decomposes and
  prioritises tasks.
- **Local extraction is the baseline** (PDF/PPTX/HTML → text with stable chunk IDs → citations work
  with every vendor); native PDF input only as an optional high-fidelity mode (~3× tokens).
- Tutor: own **read-only tutor loop** in Rust reusing the v0.1 MCP tool set in-process (≤ 8 tools).
  Models with weak tool calling degrade to retrieve-then-answer (single turn), not prompt-simulated
  tool loops. Estimated 6–9 person-weeks for provider layer + tutor loop v1.
- Optional: **ACP host** for a student's own coding agent (Codex, Claude Code, OpenCode, Qwen Code…),
  read-only by default and gated per course AI policy. Codex is no longer the default embedded agent
  (it cannot cover Claude or every BYOK vendor).
- Reminders stay deterministic (v0.2): tray + autostart + catch-up on launch; Tauri's notification
  plugin cannot schedule on desktop.

Cost (research estimate, current list prices, 5 courses, active use ≈ 2.3M input + 0.15M output
tokens/month): cheapest tier ≈ US$0.2–0.5/month, mid (Haiku-class) ≈ $1.7, frontier ≈ $3.4.
Default budget cap US$3–5/month with visible usage; main risks are default-on thinking and native PDF.

## 5. Compliance checklist (must pass before v0.3 ships)

- Reuse the v0.1 rule (ARCHITECTURE §3 rule 8): one-time disclosure, per-course `ai_access` switch
  default on, material text withheld for courses the student marked `prohibited`. The embedded
  generator must honour the same `AiMaterialsState` as the MCP server.
- Canvas API Policy §2E: disclose GAI use, storage/training per provider, label AI-generated output.
- Provider eligibility per vendor terms (some require 18+; verify per provider — don't copy consumer
  terms onto API terms) and data location (some vendors keep data in China; show it).
- Content moderation: surface vendor refusal/error codes clearly (some vendors also rewrite silently).
- StudentOS privacy policy (needed once we integrate with ChatGPT/Claude surfaces).
- Written confirmation from Anthropic for mode B; re-check OpenAI Codex terms for mode A.
